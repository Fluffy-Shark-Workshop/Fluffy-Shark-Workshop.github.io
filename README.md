# Fluffy Shark Workshop 블로그

공부한 내용을 빠르게 올리기 위한 GitHub Pages 블로그입니다.

- 주소: <https://fluffy-shark-workshop.github.io>
- 올릴 수 있는 것: **Markdown, HTML, PDF, 이미지**. 올리면 내용 전체가 본문에 펼쳐집니다.
  - PDF는 모든 쪽이 차례대로 보입니다.
  - HTML은 페이지 높이 전체가 보이고, 안의 스크립트도 동작합니다.
  - Markdown의 `$...$`, `$$` 수식은 `보고서_작성_가이드_v2.2`의 규칙 그대로 MathJax 3로 표시됩니다.
- 왼쪽에 프로필 사진, 검색(태그 자동완성, 초성 검색), 카테고리, 태그가 있습니다.

## 글 올리기: 글쓰기 도구

1. `블로그 글쓰기.bat`을 더블클릭합니다. 올릴 파일이나 폴더를 이 아이콘 위에 끌어다 놓아도 됩니다.
   처음 한 번은 필요한 파이썬 패키지를 설치하느라 조금 걸립니다.
2. 브라우저에 글쓰기 화면이 열리면 파일을 끌어다 놓거나 **파일 선택**을 누릅니다.
3. 제목(파일에서 자동으로 채워짐), 카테고리, 태그를 적습니다. 카테고리와 태그는 이미 쓰던 이름이 자동완성됩니다.
4. **저장하고 게시하기**를 누르면 GitHub에 올라가고, 1~2분 뒤 블로그에 반영됩니다.

**글 관리** 탭에서는 이미 올린 글의 제목, 날짜, 카테고리, 태그, 본문을 고치거나 글을 지울 수 있습니다.
태그나 카테고리 이름을 모든 글에서 한 번에 바꾸거나 합칠 수도 있습니다.
수정이나 삭제는 상단의 **게시하기**를 눌러야 블로그에 반영됩니다.

- **Markdown·HTML 안의 이미지도 함께 올라갑니다.** `![](assets/fig1.png)`처럼 상대 경로로 참조한 파일을 찾아 폴더 구조 그대로 복사합니다.
  브라우저에 끌어다 놓은 파일은 원래 위치를 알 수 없어서, **설정 → 원본 폴더**에 등록한 폴더(예: 구글 드라이브)에서 같은 이름과 크기의 파일을 찾아 원본으로 씁니다.
- **파일 탐색기에서 바로 올리기**: `tools\install_sendto.ps1`을 마우스 오른쪽 버튼 → *PowerShell에서 실행*하면,
  파일을 고른 뒤 오른쪽 버튼 → **보내기 → 블로그에 올리기**로 글쓰기 화면을 열 수 있습니다.
- 파일 하나는 100MB를 넘을 수 없습니다(GitHub 제한). 블로그 전체는 1GB 이하로 유지하는 것이 좋습니다.

## 글의 구조

글 하나는 `posts/` 아래 폴더 하나입니다. 글쓰기 도구가 만들어 주지만, 직접 만들어도 됩니다.

```text
posts/
└─ 2026-09-26-에피폴라-기하학/
   ├─ index.md                  ← 글 정보와 본문
   ├─ 19_에피폴라_기하학_v1.1.md
   ├─ assets/fig1.png           ← md가 참조하는 이미지
   ├─ 필기1.png
   └─ 필기2.png
```

`index.md`:

```markdown
---
title: 에피폴라 기하학 정리
date: 2026-09-26 14:30
category: 공부/Visual SLAM        # '/'로 하위 카테고리
tags: [SLAM, 에피폴라, 기본행렬]
description: 목록에 보일 한 줄 설명 (선택)
pin: true                          # 첫 화면 맨 위 고정 (선택)
draft: true                        # 초안: 블로그에 안 보임 (선택)
---

짧은 설명을 적어도 됩니다.

![](19_에피폴라_기하학_v1.1.md)

![](필기1.png)
![](필기2.png)
```

- `index.md` 없이 파일만 든 폴더도 글이 됩니다. 폴더 이름(`날짜-제목`)이 제목과 날짜가 되고, 파일이 이름 순서대로 보입니다.
- 폴더 이름이 글 주소가 됩니다: `https://fluffy-shark-workshop.github.io/posts/폴더이름/`

### 첨부 파일 문법

| 적는 법 | 보이는 모습 |
| --- | --- |
| `![](필기.png)` | 이미지. 본문 폭까지 크게, 누르면 확대 |
| `![](강의.pdf)` | PDF 모든 쪽 (화면 근처 쪽만 그려서 수십 쪽도 가벼움) |
| `![](보고서.html)` | HTML 페이지 전체 높이 (내부 목차 링크도 동작) |
| `![](정리.md)` | 다른 Markdown 파일을 그 자리에 펼침 |
| `![](영상.mp4)` | 동영상 플레이어 |
| `![](코드.zip)` | 내려받기 카드 |
| `![](작은그림.png){width=300}` | 이미지 크기 지정 |

이미지를 연달아 둘 때:

```markdown
![](1쪽.png)
![](2쪽.png)      ← 바로 아랫줄: 틈 없이 붙어서 한 장처럼 보임

![](3쪽.png)      ← 빈 줄을 두면: 간격을 두고 떨어짐
```

### 수식

- 문장 속 수식은 `$...$`, 큰 수식은 `$$` 줄로 감쌉니다. `\(...\)`, `\[...\]`, ```` ```math ```` 블록도 됩니다.
- 수식은 Markdown 변환 **전에** 잘라 두었다가 그대로 되돌리므로 `_`, `*`, `\\`, `\{`, 표 안의 `|`가 깨지지 않습니다.
  (`md2html_report_v2_2.py`와 같은 방식입니다.)
- 꼭지 아래 네 칸 들여쓴 `$$` 블록, `aligned`의 `\\` 줄바꿈, `bmatrix` 모두 그대로 동작합니다.
- 달러 기호를 글자로 쓰려면 `\$`로 적습니다.

## 카테고리와 태그

- 글마다 `category` 하나(하위는 `/`로), `tags` 여러 개를 적습니다.
- 사이드바의 카테고리 순서는 `site.yml`의 `category_order`로 정합니다. 적지 않은 카테고리는 가나다순입니다.
- 카테고리별, 태그별 글 목록은 자동으로 만들어집니다: `/categories/…`, `/tags/…`
- 사이드바 검색창에 `#`을 치면 태그가 자동완성되고, `ㅅㄹ`처럼 초성으로도 찾을 수 있습니다. `/` 키를 누르면 검색창으로 갑니다.

## 설정과 꾸미기

- `site.yml`: 블로그 이름, 소개 글, GitHub 주소, 카테고리 순서, 사이드바 태그 수
- 프로필 사진: `theme/static/img/avatar.jpg`를 바꾸면 됩니다(정사각형 권장).
- 본문 최대 폭: `theme/static/css/blog.css`의 `--content-max` (지금 1680px)
- 화면 틀: `theme/templates/`, 동작: `theme/static/js/`

## 컴퓨터에서 미리 보기

```bat
.venv\Scripts\python.exe tools\build.py --serve
```

<http://127.0.0.1:4000> 에서 보입니다. 글쓰기 도구의 **미리보기**도 같은 화면입니다.

## 배포

`main` 브랜치에 올리면 GitHub Actions(`.github/workflows/deploy.yml`)가 `tools/build.py`로 사이트를 만들어 GitHub Pages에 올립니다.
진행 상황은 저장소의 **Actions** 탭에서 볼 수 있습니다.

## 폴더 구성

| 경로 | 내용 |
| --- | --- |
| `posts/` | 글 (폴더 하나가 글 하나) |
| `site.yml` | 블로그 설정 |
| `theme/` | 화면 틀(templates), CSS, JS, 프로필 사진 |
| `tools/build.py` | 사이트 생성기 |
| `tools/mdrender.py` | Markdown·수식·첨부 파일 변환 |
| `tools/writer.py`, `tools/writer/` | 글쓰기 도구 |
| `블로그 글쓰기.bat` | 글쓰기 도구 실행 |

## 문제가 생기면

- **게시하기가 실패함**: 처음 게시할 때 GitHub 로그인 창이 뜹니다. 로그인한 뒤 다시 **게시하기**를 누르세요.
  다른 컴퓨터에서 고친 내용이 있으면 도구가 먼저 받아 온 뒤 올립니다.
- **수식 하나가 이상함**: 글 페이지에서 빨간 글씨로 보이는 TeX 오류를 고치거나, `$` 짝이 맞는지 확인하세요.
- **이미지가 '파일 없음'으로 보임**: md 안의 경로와 실제 파일 이름이 같은지 확인하세요(대소문자 포함).
